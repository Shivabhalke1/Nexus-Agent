## 2. Core Privacy & Security Invariant Audits

### Invariant 1: Zero Raw Credentials in Application Logs
- **Rule**: Application logs must never contain plain-text passwords, tokens, API keys, or connection strings.
- **Implementation**: `CollectorJsonFormatter` and `sanitize_dict` recursively mask sensitive keys (`password`, `secret`, `token`, `api_key`, `authorization`, `cookie`) and regex-match Bearer tokens.
- **Verification**: Verified via `test_log_sanitizer` and structured log inspection during live collection.
- **Audit Result**: **PASS**

### Invariant 2: Zero Raw Credentials in Egress Payloads
- **Rule**: Outbound telemetry transmitted to Central SaaS must be sanitized and verified clean prior to egress.
- **Implementation**: `DataProtectionEngine` replaces sensitive fields with standard tokens (`[REDACTED_EMAIL]`, `[REDACTED_SECRET]`, `[REDACTED_TOKEN]`, `[REDACTED_DB_CREDENTIAL]`, `[REDACTED_PRIVATE_KEY]`) and executes a post-protection re-scan with `SensitiveDataDetector`. Any unredacted secret triggers a `ProtectionVerificationError`.
- **Verification**: Verified via `test_e2e_secret_injection_and_sanitization` and `test_protection.py`.
- **Audit Result**: **PASS**

### Invariant 3: Mandatory Human Approval Before Transmission
- **Rule**: Telemetry must NEVER be transmitted automatically upon collection. Outbound dispatch requires explicit authenticated administrator action.
- **Implementation**: Egress client (`SaaSClient`) only accepts `ApprovedSubmission` objects generated by `ApprovalService.approve()`, which requires an authenticated admin JWT session (`POST /api/v1/approval/{request_id}/approve`).
- **Verification**: Verified via `test_approval.py` and `test_pipeline_e2e.py`.
- **Audit Result**: **PASS**

### Invariant 4: Hard Policy Blocks Cannot Be Overridden
- **Rule**: If a payload violates hard privacy rules (e.g. unsanitized state, residual secrets, prohibited fields, oversized payload), administrators cannot override the block.
- **Implementation**: `PolicyValidator` sets `can_be_approved = False`. `ApprovalService.approve()` explicitly checks this flag and raises `PolicyViolationBlockedError` (HTTP 400), halting the approval lifecycle.
- **Verification**: Verified via `test_approval_blocked_on_policy_violation` and `test_e2e_rejection_and_policy_block`.
- **Audit Result**: **PASS**

### Invariant 5: Cryptographic Integrity & Anti-Tampering
- **Rule**: The exact payload inspected and approved by the administrator must be the identical payload transmitted to Central SaaS.
- **Implementation**:
  1. At approval creation, a canonical SHA-256 hash (`sort_keys=True`, compact separators) is computed.
  2. At approval time, the hash is re-verified.
  3. Pre-transmission, `SaaSClient` re-computes the hash immediately before dispatch and aborts with `TransmissionTamperError` if any mutation is detected.
- **Verification**: Verified via `test_approval_tamper_detection` and `test_saas_transmission_blocks_on_tampered_payload`.
- **Audit Result**: **PASS**
